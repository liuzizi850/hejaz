# REQ-002 验收说明（本地）

本页给验收人员和系统管理员。测试人员只通过后台页面操作，不使用命令行，也不配置密钥。

## 测试人员路径（页面）

1. 使用现有后台账号登录。
2. 打开 APP 自动化模块中的「执行与报告」页面（路由 `/app-automation/ai-run`）。
3. 勾选预置 BDD 脚本，或上传一个 `.feature` 文件。
4. 在已连接设备列表中选择一台当前在线的 Android 设备（若列表为空，待设备就绪后点击刷新；本页不提供启动模拟器或 Scrcpy 安装/连接引导）。
5. 点击「开始执行」。页面会显示进行中状态。
6. 执行完成后，在本页查看含用例名称、通过/失败、失败原因和截图的报告。
7. 可下载 zip（需登录），解压后可离线打开 `index.html` 与截图。
8. 可复制分享链接。持有该链接的人无需登录即可只读查看同一份报告；下载与再次执行仍需登录。无效链接无法访问。

未登录无法使用上传、选择、执行和打包下载。若执行服务未就绪，页面会提示「执行服务未就绪」，而不会静默挂起。

## 管理员环境准备（不对测试人员展示为使用步骤）

本功能依赖本机已有条件，页面不会补齐环境：

- Web 服务与 Celery worker 已按现有方式启动。worker 未启动时，测试人员只会看到「执行服务未就绪」。
- 至少一台当前已连接且 adb 状态为 `device` 的 Android 设备（本地模拟器，或已通过 USB / Scrcpy 连上的真机）。不要为了本页去调用 `ensure_emulator`。
- LLM 配置沿用 REQ-001 的本机来源（进程环境变量或已有用户级配置文件）。不要把密钥写进仓库、页面、日志或聊天。配置缺失时，测试人员只会看到「系统未配置执行环境，请联系管理员」。
- 在本 worktree 应用数据库变更（仅管理员本地操作）。项目默认忽略 migrations 文件时，请在本目录生成并执行迁移，只新增 REQ-002 的三张表（`app_ai_run_scripts`、`app_ai_run_executions`、`app_ai_run_shares`），不要改现有用例/套件表。

上传脚本保存在应用数据目录 `artifacts/req002/uploads/`，执行报告保存在 `artifacts/req002/runs/`。测试人员无需知道这些路径。

## 开发验证命令（不是测试人员步骤）

在仓库 worktree 根目录、使用项目虚拟环境执行：

- 现有 REQ-001 单测：`python -m pytest tools/req001/tests -q`
- 适配层单测（无真机、无真实 LLM）：`python -m pytest tools/req001/tests/test_run_selected.py -q`
- REQ-002 API 单测（项目 migrations 默认不入库，故使用 --nomigrations；Windows 下请加 -s，避免 pytest 捕获与 Django 日志冲突）：`python -m pytest apps/app_automation/ai_run/tests --nomigrations -s -q`
- 前端如需构建：在 `frontend` 目录执行现有 `npm run build`（如适用）

不要把 `run_mvp.py`、`manage.py` 或适配层 CLI 当作测试人员验收步骤。CLI 仅供管理员或开发排障。

## 范围确认

- 不推送、不开远程 PR、不合并主分支、不发布。
- 不重写 AI 工具循环，不走现有 UI Flow / Allure 主路径，不调用 `ensure_emulator`。
- 不引入 iOS、用例自动生成、CI/CD 或多设备并行。
- 接口与页面响应不得包含密钥、仓库绝对路径或可复制执行的命令行。
