# 代码监控：提取 API

日期：2026-11-06

首页增加「代码监控」卡片。打开后父栏目是「提取 API」，下面有代码地址、扫描任务、下载结果。这一期只做从源代码提取 API 并导出 Excel。卡片说明里的「检查代码质量」不建栏目、不做功能。

## 已定选择

- 入口是首页卡片，不是「AI 生成」下的菜单。卡片标题为「代码监控」。说明为「支持从源代码中提取 API，也支持从源代码中检查代码质量」。点击后新标签打开 `/code-monitor`。
- 页面两层：父栏目「提取 API」；子栏目「代码地址」「扫描任务」「下载结果」。
- 代码可以是前端、后端，或两者在同一仓库。不按技术栈写解析器。大模型负责识别并抽取接口。
- 来源是已保存的 Git 地址，或当次上传的 zip。私有仓库的访问令牌只用于当次克隆。
- 只读源码。不安装依赖，不运行项目。
- 先在服务器上筛整棵目录，再把候选文件分批送给模型。不因仓库体积或候选文件数量拒绝任务。
- 模型返回固定 JSON。汇总去重后写成 Excel。抽出的接口不另存业务表，Excel 就是结果。
- 复用现有 AI 模型配置和 Celery。不写入 API 测试模块的可执行请求。
- 地址、任务、结果只显示当前登录用户自己的。

## 页面

首页卡片与现有卡片相同：点击后 `window.open` 到新标签。中英文案写进首页现有的 i18n 文案。英文标题为 “Code Monitoring”，说明为 “Extract APIs from source code, and check code quality from source code.”

`/code-monitor` 只渲染「提取 API」。三个子栏目：

- **代码地址。** 列表显示名称和 Git 地址。可以新增、删除。不上传 zip，不保存令牌。
- **扫描任务。** 选择一条已保存地址，或上传 zip。私有仓库在这里填写令牌。再选择一条已启用的 AI 模型配置，提交。列表显示状态、进度和失败原因。
- **下载结果。** 只列出成功任务，提供 Excel 下载。失败任务留在扫描任务里。

没有已启用的模型配置时，不能提交扫描。

## 扫描流程

1. 创建任务，状态为待执行，交给 Celery。
2. Git 则克隆到临时目录；zip 则解压到临时目录。这一步限时 10 分钟。令牌只作为本次克隆参数，不写入地址、任务字段和日志。
3. 走过整棵目录，得到候选文件。
4. 按批发送。每批输入不超过 60000 个字符；单个文件超过上限时按行切开，每段单独成批，文件内容不丢弃。
5. 每批要求模型只根据给定代码输出 JSON 数组。字段为名称、请求方式、请求地址、入参、出参、源文件。代码里看不出的入参、出参用空字符串。禁止补写代码中没有的接口和字段。
6. 丢掉没有请求方式或请求地址的条目。按「请求方式 + 请求地址」去重：只留一行；入参、出参保留先得到的非空内容；源文件把命中的路径用逗号拼在一起。
7. 写成 Excel。列顺序为：名称、请求方式、请求地址、入参、出参、源文件。
8. 任务改为成功，文件出现在下载结果。删除临时目录。任务进入成功或失败后，删除上传的 zip，只保留 Excel。

进度用已完成批数除以总批数。

同一用户对同一地址可以再次扫描，每次新开一条任务和一份 Excel。

## 筛文件

筛文件只决定哪些文件送给模型，不抽取接口。

不读这些目录和文件：`.git`、`node_modules`、`venv`、`.venv`、`dist`、`build`、`__pycache__`，以及锁文件、图片、压缩包和其他二进制文件。

留下文本文件，只要满足其一：

- 路径中含 `api`、`router`、`controller`、`views`、`urls`、`serializer`、`route`
- 内容中含 `axios`、`fetch`、`urlpatterns`、`@GetMapping`、`@PostMapping`、`@PutMapping`、`@DeleteMapping`、`@PatchMapping`、`app.get`、`app.post`、`app.put`、`app.delete`、`router.get`、`router.post`、`router.put`、`router.delete`

一个候选文件都没有时，任务失败，原因写明没有找到像接口定义的文件。

## 失败

失败的任务停在扫描任务，写明原因。下载结果里不出现文件。临时目录在结束时删除。

- 取代码失败：地址无效、私有仓库没有可用令牌、zip 打不开、克隆或解压超时。
- 模型某一批失败：该批重试一次。仍失败则整次任务失败。已经抽成功的批次不写入 Excel。
- 模型返回的内容不是合法 JSON 数组：视同该批失败。

不设解压体积上限，也不设候选文件数量上限。

## 数据

新应用 `apps/code_monitor`。

**代码地址**

- 名称
- Git 地址
- 创建者
- 创建时间

**扫描任务**

- 来源类型：`git` 或 `zip`
- Git 地址（zip 任务为空）
- 上传的 zip（Git 任务为空）
- 所选 AI 模型配置
- 状态：待执行、执行中、成功、失败
- 进度：0 到 100
- 失败原因（成功时为空）
- Celery 任务 ID
- 结果 Excel（成功后才有）
- 创建者
- 创建时间、更新时间

访问令牌不是这两个模型的字段。

## 测试

模型调用使用假响应，不请求真实模型。

- 筛文件时，依赖目录、构建产物和二进制文件不进候选；路径或内容命中规则的文本文件留下。
- 没有请求方式或请求地址的条目被丢掉。入参、出参可以为空。
- 同一请求方式和地址只剩一行。多个源文件路径保留在源文件列。
- Excel 列顺序与上面一致。
- Git 地址无效、zip 打不开、没有候选文件、重试后仍是非法 JSON：任务失败且没有结果文件。
- 提交扫描时带上的令牌不出现在地址库和任务记录中。
- 用户只能看到自己的地址、任务和结果。
- 首页存在「代码监控」卡片，打开后的父栏目是「提取 API」，其下为代码地址、扫描任务、下载结果。
