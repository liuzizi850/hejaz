# Android 事件链录制与回放

日期：2026-11-04

第一期只做 Android。人在真机上操作，平台通过无障碍服务记下事件链；以后每次执行前由人把手机拨到开始界面，平台核对后自动回放，并交出 Word、录屏和截图组成的结果包。

## 已定选择

- 人直接操作真机。平台点「录制」后，手机上的无障碍服务开始听点击、滑动和输入。
- 每一步保存控件身份和该控件区域截图。回放时先找控件，找不到再用截图做图像匹配。
- 断言在电脑上标。手机停在目标界面后，点「标为断言」，勾选要校验的文字或控件。
- 普通操作只检查「找到目标并完成操作」。任一步失败，用例失败并停止后续步骤。
- 平台不打开应用。用例保存一张开始界面全屏截图。点「启动」时先比对当前屏幕，不像就拒绝，不录屏。
- 报告是一个压缩包：`report.docx`、mp4、`screenshots/`。Word 里只写文件名。失败时已产生的视频和截图仍然留在包里。
- 事件格式预留 `ios`，这一期不实现 iOS 录制和回放。

## 录制

1. 在录制页选择一台已连接的 Android 设备，点「录制」。
2. 平台确认设备在线，且「TestHub 录制服务」已在系统无障碍设置中打开。然后建立录制会话。
3. 人直接操作手机。服务把点击、长按、滑动、输入推到平台，录制页按到达顺序显示。
4. 需要断言时，人让手机停在目标界面，在电脑上点「标为断言」。平台抓取当前界面的文字和控件，人勾选后插入一条断言步骤。
5. 点「停止」后，可以删除误触、调整顺序、补上等待，再保存为用例。
6. 保存时写入事件链，并保存当时的开始界面全屏截图。开始界面是点「录制」那一刻的屏幕，不是停止时的屏幕。

等待不是系统事件，只能在停止后手工加入。密码框若系统不给出原文，该步文字为空，可以保存；页面标出这一步，回放执行到它时判失败，不向输入框写入空字符串。

同一台设备已在录制或回放时，拒绝再开始，沿用现有设备锁定。

## 回放

1. 人把手机拨到与开始界面一致的画面，选择设备和这条用例，点「启动」。
2. 执行任务看到用例带有事件链，交给事件链回放器。没有事件链的用例仍只跑原来的 `ui_flow`。
3. 回放器截取当前屏幕，与开始界面截图比对。比对前裁掉屏幕顶部 8%，避免状态栏时钟变化造成误判。图像匹配使用 Airtest Template 的默认阈值。
4. 不像：不录屏、不执行步骤。执行结果为失败，附上当前屏和开始界面两张图。
5. 像：开始 `adb` 录屏，再按事件链顺序回放。每一步留下截图。
6. 任一步失败则停止后续步骤，停止录屏，已完成的步骤结果保留。未执行的步骤记为未执行。
7. 打包结果。定时任务和套件跑到事件链用例时，同样先做开始界面比对。

## 事件链

事件链存在用例上，与 `ui_flow` 分开。模板图放在 `media/app-automation/recordings/<case_id>/`。

除 `wait` 以外，每一步都有：

- `type`：`click`、`long_press`、`swipe`、`input`、`assert`
- `platform`：这一期为 `android`
- `order`
- `name`：给人看的说明
- `resource_id`、`content_desc`、`text`、`class_name`
- `bounds`：录制时控件区域相对屏幕的位置，取值 0 到 1
- `template`：控件区域截图的相对路径。断言步改为保存标定时的整屏截图
- `screen`：录制时屏幕宽高

`wait` 只有 `type`、`platform`、`order`、`name`、`duration_ms`。

各类型额外字段：

| type | 额外字段 | 回放 |
| --- | --- | --- |
| `click` / `long_press` | `duration_ms` | 找到控件后点击或长按 |
| `swipe` | `direction`（up / down / left / right）、`distance`（相对被滑区域边长的比例，0 到 1），以及被滑区域的控件身份 | 在该区域上滑动 |
| `input` | `input_text` | 找到输入框后写入。`input_text` 为空则该步失败 |
| `wait` | `duration_ms` | 只等待，不查找控件 |
| `assert` | `expected_texts`（字符串列表）、`expected_selectors`（与控件身份相同的对象列表） | 当前界面树中须同时出现这些文字和控件。文字不走图像匹配 |

`ios` 相关字段保留为空：`accessibility_id`。这一期不读、不写业务值。

点击、长按、滑动、输入的查找顺序：

1. 有 `resource_id` 时按它找。
2. 否则用 `content_desc`。
3. 否则用 `text` 加 `class_name`。
4. 找到多个时，选离 `bounds` 最近的一个。
5. 一个都找不到时，用 `template` 做图像匹配。
6. 仍然找不到，该步失败，用例停止。

滑动若无障碍服务只给出滚动、不给出像素轨迹，记为方向和距离，不记成裸坐标。

## 模块

手机侧是独立的小型 Android 工程，只含无障碍服务，不负责回放。服务把事件发到手机本机端口，电脑用 `adb reverse` 转到 Django。端口固定为 `27183`。`adb` 能连上的真机和模拟器都走这条路径，手机不配置服务器地址。

平台侧：

- `AppTestCase` 增加 `event_chain`（JSON）和开始界面截图路径。
- 录制会话接口放在现有 APP 自动化设备接口旁边：开始、停止、接收事件、抓取当前界面供断言。实时步骤用现有 WebSocket 推到录制页。
- 新增 `EventChainRunner`。控件身份用 uiautomator 查找，图像匹配用现有 Airtest Template。开始界面比对在进入录屏之前完成。
- 执行结束处打包 Word 和压缩包。执行记录增加结果压缩包路径。`ui_flow` 用例继续生成 Allure 报告。
- 前端新增录制页：选设备、开始、事件列表、标为断言、停止、删改步骤、保存。执行详情提供压缩包下载。设备列表和用例列表保持原入口。

`report.docx` 包含步骤表：顺序、名称、类型、结果、截图文件名、失败原因，以及按顺序排列的 mp4 文件名。文档内不嵌入图片或视频。

单段 `adb` 录屏达到设备上限（按 180 秒）时，结束当前段并立即开始下一段。压缩包内为 `video-1.mp4`、`video-2.mp4` 这样的顺序文件名。

## 失败处理

- 设备不在线或录制服务未打开：不创建会话。页面说明要在系统设置中打开「TestHub 录制服务」，并提供重新检查。
- 录制中途断开或服务停止：已收到的步骤保留，会话标为中断。可以保存这些步骤，也可以放弃。
- 标为断言时抓不到界面：不插入步骤，提示重试。
- 开始界面不匹配：结果失败，只保留两张对照图，不生成含视频的结果包。
- 步骤失败：该步截图留下，后续步骤记为未执行，停止录屏，仍生成完整结果包。
- 录屏命令失败：步骤继续执行，截图照留。压缩包中没有 mp4，Word 中写明录屏失败。
- 打包失败：用例成败仍按步骤结果计算。页面提示报告未生成，截图和视频留在该次执行目录。

回放设备与录制设备的分辨率差异较大时，开始界面比对和模板匹配可能失败。控件身份查找仍然有效。

## 验收

自动测试：

- 事件链按顺序保存五类步骤，并带上控件身份和模板图路径。
- 查找顺序为 `resource_id`、`content_desc`、`text` 加 `class_name`、`bounds` 挑选、模板图。
- 开始界面不匹配时不调用录屏。
- 某步失败后不再执行后续步骤，已有截图进入结果。
- 压缩包含 Word 和截图目录；有录屏时含 mp4，录屏失败时 Word 写明没有视频。Word 中只有文件名。
- 手写 `ui_flow` 用例不进入事件链回放器。

真机：

1. 服务未打开时点「录制」，只出现提示，没有会话。
2. 打开服务后录下点击、输入、滑动，标一条文字断言，删掉一步误触，补一个等待，保存成用例。
3. 停在其他界面点「启动」，被拒绝，能看到当前屏和开始界面。
4. 拨回开始界面再启动，回放完成，压缩包中有 Word、mp4 和每步截图。
5. 把断言改成错误文字再跑，用例失败并停在该步，压缩包仍在，后续步骤为未执行。
