# REQ-001 MVP 本地操作说明

本页说明如何在 Windows 上用一条命令跑通：

**拉起或复用官方 Android 模拟器 → 探测预装计算器（否则安装仓库备选 APK）→ AI 自动执行 3 条示例 BDD → 生成本地 HTML 报告。**

不经过用例管理后台，不以 Allure / Scrcpy 为验收路径，也不做 iOS、CI/CD 或用例生成。只在本地分支验证，不要推送或合并主分支。

## 1. 环境依赖

- Windows，项目虚拟环境建议使用仓库中的 `.venv312`（Python 3.12）。
- JDK 17+，并设置 `JAVA_HOME`。
- Android SDK，建议设置 `ANDROID_SDK_ROOT`（常见路径：`%LOCALAPPDATA%\Android\Sdk`）。
- 必需组件：`platform-tools`（adb）、`emulator`、至少一个 AVD，以及一条 **x86_64** 系统镜像。
- 本仓库默认按 API 34 Google APIs x86_64 创建 AVD `REQ001_API34`：

```bat
set SDK=%LOCALAPPDATA%\Android\Sdk
%SDK%\cmdline-tools\latest\bin\sdkmanager.bat --sdk_root=%SDK% --licenses
%SDK%\cmdline-tools\latest\bin\sdkmanager.bat --sdk_root=%SDK% --install platform-tools emulator platforms;android-34 "system-images;android-34;google_apis;x86_64"
echo no| %SDK%\cmdline-tools\latest\bin\avdmanager.bat create avd -n REQ001_API34 -k "system-images;android-34;google_apis;x86_64" -d pixel_4
```

首次下载系统镜像体积较大，需要网络。请在「Windows 功能」中启用 Hyper-V 或 Windows Hypervisor Platform / 虚拟机平台。

只检查环境、不启动模拟器：

```bat
.venv312\Scripts\python.exe tools\req001\ensure_emulator.py --check-only
```

拉起或复用模拟器（adb 已能看到在线模拟器时不会重复拉起；等待 `adb wait-for-device` 且 `sys.boot_completed=1`）：

```bat
.venv312\Scripts\python.exe tools\req001\ensure_emulator.py
```

缺失 adb / emulator / 镜像 / AVD 时，脚本会打印可执行的安装命令，而不会静默失败。不依赖 Scrcpy。

若控制台默认代码页无法显示中文（例如 cp1252），可先设置后再运行同一条命令（脚本本身也会尽量避免因打印中文而异常退出）：

```bat
set PYTHONUTF8=1
.venv312\Scripts\python.exe tools\req001\run_mvp.py
```

## 2. 配置 LLM（OpenAI 兼容接口）

实现不绑定某一供应商。API Key、base URL 与模型名都只从本机环境变量或本地配置文件读取，**不会把密钥写入代码、日志、报告或仓库**。请勿把配置文件复制进仓库，也不要把密钥贴进聊天。

按优先级识别以下变量名：

| 用途 | 变量名（前者优先） |
|------|-------------------|
| API Key | `DASHSCOPE_API_KEY`，或 `OPENAI_API_KEY` / `REQ001_OPENAI_API_KEY` |
| base URL | `base_url`，或 `OPENAI_BASE_URL` / `REQ001_OPENAI_BASE_URL` |
| 模型 | `COMMIT_REVIEW_MODEL`，或 `OPENAI_MODEL` / `JUDGE_MODEL` / `REQ001_OPENAI_MODEL` |

本机还会在运行时尝试读取用户级配置文件（存在才用，不复制、不打印内容）：

`C:\Users\EmmaLiu\.commit-review.env`

该文件中的 `DASHSCOPE_API_KEY`、`base_url`、`COMMIT_REVIEW_MODEL` 优先于仓库根目录 `.env` 里可能不匹配的 `OPENAI_*`。`.commit-review.env` 与 `.env` 均已被 git 忽略。也可用环境变量 `REQ001_LLM_ENV_FILE` 指向其他本地文件（单元测试用临时夹具，不读真实密钥文件）。

在 git worktree 中运行时，脚本还会尝试读取**主工作区**里已有的 `.env`，但不会复制或打印它。缺少配置时命令会明确失败并提示如何设置，不会退回人工点选。

## 3. 一键试跑

在当前 checkout / worktree 根目录执行（优先项目 venv）：

```bat
set PYTHONUTF8=1
.venv312\Scripts\python.exe tools\req001\run_mvp.py
```

或：

```bat
set PYTHONUTF8=1
.venv312\Scripts\python.exe manage.py run_req001_mvp
```

不需要启动前端或 Celery。

命令会：

1. 复用已在线模拟器，或拉起官方 AVD；
2. 运行时探测预装计算器（标签含「计算器 / Calculator / Calc」，或包名命中提示表中**已安装**的项）。提示表不会假定包一定存在；
3. 若零命中，安装 `fixtures/apk/` 中的公开备选 APK，包名来自 `aapt dump badging`；
4. 在需要计算的用例开始前检查数字键区是否可见；若不可见会先尝试重启应用，仍不行再尝试重启模拟器。若仍然空白，该用例记为失败并提示重启模拟器后重跑，不会当作平台崩溃；
5. 用 AI 逐步工具循环执行 `fixtures/bdd/` 下 3 条中文夹具；
6. 在 `artifacts/req001/<run_id>/index.html` 写出可直接用浏览器打开的报告。

S1、S2 期望通过；S3 是故意失败的断言，报告中应为失败并带可读原因和截图。**即使模型把 S3 记为通过，编排层仍会在报告中强制标记为失败。** 编排命令在平台本身成功时退出码为 0（夹具失败不等于平台崩溃）。

### 计算器键区空白时

备选计算器在个别模拟器会话里可能出现键区空白（界面只剩 DEG、数字键不可见或无法点击）。这时请：

1. 关闭并重新启动官方模拟器（或先结束模拟器进程后再运行下面的命令）；
2. 再执行同一条命令：`python tools\req001\run_mvp.py`。

不要改命令本身。脚本若已自动尝试重启应用或模拟器仍未恢复，报告里会写明上述原因。

## 4. 查看报告

用浏览器打开：

`artifacts/req001/<run_id>/index.html`

摘要中包含：设备序列号、实际采用的包名、走的是预装计算器还是备选 APK。无需 Allure。
